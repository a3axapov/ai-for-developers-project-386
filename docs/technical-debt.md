# Технический долг

## TD-001 — единая команда проверок с Docker

**Статус:** отложено по согласованию.

Сейчас `mise run check` выполняет основные проверки без Docker. В CI сборка
образа и контейнерный smoke test запускаются отдельными шагами:
`mise run image:build` и `mise run image:test`.

**Вернуться к задаче:** определить единую полную проверку для локального запуска
и CI, сохранив возможность быстрых проверок без Docker.

**Критерии закрытия:**

- Одна документированная команда выполняет основные проверки, сборку образа
  и контейнерный smoke test в нужном порядке.
- GitHub Actions вызывает эту же команду.
- Отсутствие Docker диагностируется явно; обязательные проверки не пропускаются
  молча.

## TD-002 — политика npm audit

**Статус:** отложено по согласованию.

Сейчас `mise run audit` выполняется отдельно и не входит в обязательный gate.
Зелёный `mise run check` не означает отсутствие известных уязвимостей.
Исходный отчёт и ограничения совместимости описаны в
[docs/toolchain.md](toolchain.md#известные-предупреждения-npm-audit).

**Вернуться к задаче:** согласовать обработку advisory для runtime-зависимостей
и инструментов разработки, порог блокировки CI и порядок устранения или
временного принятия риска.

**Критерии закрытия:**

- Политика документирована, включая правила исключений, ответственного
  за исключение и срок его пересмотра.
- Известные advisory пересмотрены: устранены совместимыми обновлениями либо
  имеют обоснованные временные исключения по принятой политике.
- Проверка в CI следует этой политике и явно сообщает о нарушениях.
- Принудительное обновление через `npm audit fix --force` и несовместимые
  подмены зависимостей не используются как способ скрыть предупреждения.
