# Передача работы, восстановление и публикация

## Текущая граница продукта

Реализация спецификации [#13](https://github.com/a3axapov/ai-for-developers-project-386/issues/13)
**приостановлена перед #20**. Срезы #14–#19 закрыты; исходная точка ретроспективы
— `bff6989a8d22ca3cad31135ca9d5df77b545ef71` в `integration/spec-13`.
Задача сопровождения #35 не разрешает начинать #20 или следующие продуктовые срезы.
Возобновление требует явной команды владельца проекта. Статус приёмки #35,
последний проверенный SHA и CI следует брать из её комментариев, а не из этого файла.

## Начало и восстановление

1. Выполнить `pwd`, `git status --short`, `git branch --show-current`,
   `git rev-parse HEAD` и `git worktree list`. Не перезаписывать незнакомые изменения.
2. Читать **AGENTS.md фактического worktree**, затем тематические документы по ссылкам.
   Сравнить `git log -1 --format='%H %s' -- AGENTS.md docs/agents` с интеграционной
   веткой: инструкции в соседнем/main worktree не становятся автоматически локальными.
   Пользовательское обновление `ac23d6c` перенесено в #35 обычным merge с сохранением
   исходного коммита. Дальнейшую синхронизацию согласовывать, не сбрасывать ветки.
3. Получить сначала номера/заголовки, затем только нужный ticket, зависимости
   и применимые разделы спецификации. Например:

   ```sh
   mise exec github-cli@latest -- gh issue view 35 --json number,title
   mise exec github-cli@latest -- gh issue view 35 --json body,comments
   ```

4. Прочитать последний вердикт ревью **с его точным SHA** и финальные доказательства
   в ticket. Старые `/tmp`-отчёты, ORCHESTRATION.md и BATCH-WORKFLOW.md — лишь
   вспомогательная история, не актуальные инструкции и не доказательство приёмки.
5. После bootstrap выполнить `mise run doctor`. Chromium запускается напрямую,
   без `LD_LIBRARY_PATH` и других обходов отсутствующих библиотек. При отсутствии
   системных пакетов остановиться и запросить установку по environment.md.
6. Проверить локальный checkpoint; несовпадение пути, ветки, HEAD или инструкций
   требует исследования, а не автоматического продолжения команды.

## Компактный локальный checkpoint

```sh
mise run checkpoint save 35 --stage implementing --review pending --pending check
mise run checkpoint show 35
# После независимого ревью (SHA — фактически просмотренный commit):
mise run checkpoint save 35 --stage review --review approved --review-sha <SHA> --pending none
```

Команда записывает один JSON в `<git-common-dir>/agent-checkpoints/35.json`, вне
индекса и вне временного worktree. Удаление linked worktree его не удаляет;
удаление всего репозитория удаляет и локальные metadata. Для переноса на другую
машину источником контекста остаётся GitHub ticket. Запись атомарна, права `0600`.
После осознанной смены worktree сначала прочитать старую запись непосредственно
из common-dir, сопоставить её с GitHub и только затем сохранить новую.

Схема версии 1: `ticket` (положительный номер), `branch`, `worktree` (реальный
абсолютный путь), `head` (полный SHA), `instructionsSha256` (содержимое локального
AGENTS.md), `stage`, `review: {verdict, head}`, `pendingCommand`.

- Стадии: `implementing`, `checking`, `review`, `ready`, `paused`, `blocked`.
- Вердикты: `pending`, `changes-requested`, `approved`; два последних требуют
  `--review-sha`. `ready` требует одобрения именно текущего HEAD.
- Незавершённая команда — только категория: `none`, `doctor`, `api:check`, `lint`,
  `typecheck`, `test`, `test:browser`, `check`, `image:build`, `image:test`, `push`, `ci`.
  Она **не исполняется автоматически**; неизвестно, завершился ли прежний процесс.
  Сначала проверить процессы/логи/порты. `show` предупреждает об устаревшем review SHA.
- Свободного текста, аргументов команд, токенов, секретов попыток и гостевых данных
  здесь нет. Не добавлять их вручную. Рабочий diff не сохраняется: всегда смотреть
  `git status` и незакоммиченные изменения отдельно.

Сохранять checkpoint после коммита и перед дорогой командой/передачей работы.
Не коммитить файл с SHA собственного HEAD: он неизбежно устаревает при коммите.
Это журнал возобновления, **не** свидетельство успешного check/review/CI.

## Экономные проверки и независимое ревью

- Сначала узкая воспроизводящая проверка на согласованной публичной границе;
  один red → минимальный green. Для инструментов — CLI и файловые фикстуры;
  для продукта — реальный HTTP/построенный интерфейс с настоящим сервером.
- `mise run test:tools` проверяет CLI doctor/checkpoint, маршруты и тот же comparator,
  который вызывает `api:check`. PATH-фикстура неверной версии проверяет только
  диагностику инструмента, не заменяет фактический запуск Chromium.
- `mise run api:routes` компилирует **исходный TypeSpec** через compiler/http API
  без emit и сравнивает разрешённые пути: одинаковый метод, одинаковое число
  сегментов, каждый сегмент равен либо параметризован хотя бы с одной стороны.
  Сравнение консервативно: не полагается на порядок Spring-маршрутов или имена
  параметров. Проверка защищает используемые контрактом целосегментные параметры;
  при введении иных URI-template конструкций расширить проверку и фикстуры.
- Все новые проверки включены в **тот же** `mise run check`; doctor — отдельная
  быстрая диагностика, не замена gate. Не запускать одновременно Gradle/full check/
  Playwright; порты 4173/4174 принадлежат одному прогону. Использовать явный timeout
  минимум 1 200 000 мс для полного локального gate, больше при холодном кеше.
- Передать свежему reviewer точные base/head SHA, ticket/spec sections, список
  изменений, команду/exit code/число тестов полного check и непройденные проверки.
  Reviewer сверяет **текущий** HEAD, делает независимые целевые проверки инвариантов,
  не запускает автоматически ещё один полный gate на неизменившемся дереве.
  Изменение дерева после проверки требует нового подходящего доказательства.
- Полный локальный check, обычный pre-push и CI обязательны. Независимое ревью
  и разрешение на публикацию не заменяются checkpoint или отчётом исполнителя.

## Публикация и CI точного коммита

Только после разрешения на push, в разрешённую интеграционную ветку:

```sh
GIT_SSH_COMMAND='ssh -o ServerAliveInterval=15 -o ServerAliveCountMax=3' mise exec -- git push origin integration/spec-13
mise exec github-cli@latest -- gh run list --workflow CI --commit <SHA> --json databaseId,headSha,status,conclusion,url
mise exec github-cli@latest -- gh run watch <RUN_ID> --exit-status
```

SSH keepalive подтверждён расследованием #17: без него соединение простаивало
и закрывалось примерно через 362 секунды ещё до передачи ref-update; интервал
15 секунд выдержал 540-секундную проверку и обычный push с 720-секундным hook.
Это локальная настройка одной команды, не изменение SSH-конфигурации и не обход
hook. Не использовать `--no-verify`, отключение hk или библиотечные обёртки.
На push выделить достаточный timeout с учётом **полного** pre-push; затем один
`gh run watch` с timeout не меньше 1 800 000 мс вместо частого polling.
Убедиться, что `headSha` выбранного запуска равен опубликованному SHA, и проверить
итог всех jobs. Зелёный предыдущий коммит не доказывает успех нового.

Финальный комментарий ticket: полный SHA, точные команды и результаты/числа,
что не запускалось, ссылки на CI, SHA/вердикт независимого ревью и состояние
паузы перед #20. `/tmp` допустим для логов, но не как единственное хранилище
доказательств. Не объявлять CI успешным до зелёного запуска нужного SHA.
